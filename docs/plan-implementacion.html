1. Resumen ejecutivo y stack

El sistema recibe un punto (latitud, longitud) y un radio (metros), consulta negocios cercanos en la Google Places API (nueva v1) mediante places:searchNearby, aplica dos reglas de negocio para evaluar la madurez tecnológica de cada negocio y registra prospectos junto con oportunidades de venta generadas automáticamente en Supabase.

2. Arquitectura y flujo de datos

Request (POST /api/prospectar)
   │  { latitud, longitud, radio, tipos[] }
   ▼
┌──────────────────────────────────────────────┐
│       Controller (Express / Vercel)          │  api/prospectar.ts · src/controllers
│  validación Joi · rate-limit · CORS · helmet │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│        services / prospector.ts              │
│  1. POST places.googleapis.com/v1/places:    │
│        searchNearby  (fetch + AbortController)│
│  2. evaluarReglasNegocio(place) → [A|B]      │
│  3. generarArgumentoVenta(place, servicio)    │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│        Supabase (PostgreSQL + RLS)           │
│   upsert prospectos (onConflict place_id)    │
│   insert diagnosticos (fk prospecto_id)      │
└──────────────────────────────────────────────┘
Robustez: cada lugar se procesa en su propio try/catch; un fallo de Google Places o de Supabase aborta solo ese registro, no el lote completo. Se usa AbortController (timeout 10 s) para evitar cuelgues.

4. Reglas de negocio (diagnóstico)

Regla A — Presencia Digital

Si websiteUri es nulo o vacío → oportunidad Desarrollo de Landing Page / Presencia Digital.
Prioridad: Alta

Regla B — Sistemas B2B

Si userRatingCount > 150 → oportunidad Migración a Base de Datos Relacional y Sistema de Gestión.
Alta si no tiene web Media si ya tiene web

Ambas reglas pueden activarse a la vez

Un negocio sin web y con +150 reseñas genera dos diagnósticos (dos filas en diagnosticos).

EscenarioLanding PageSistema B2B
Sin web · ≤150 reseñasSí · Alta—
Sin web · >150 reseñasSí · AltaSí · Alta
Con web · >150 reseñas—Sí · Media
Con web · ≤150 reseñas——

Argumento de venta: texto parametrizado con nombre, rating y nº de reseñas del negocio, listo para pegar en correo o WhatsApp.

Fragmento central — reglas de negocio

function evaluarReglasNegocio(place: GooglePlace): ScoreDiagnostico[] {
  const ligas: ScoreDiagnostico[] = [];
  const tieneWeb = place.websiteUri ? place.websiteUri.trim().length > 0 : false;
  const altoVolumen = (place.userRatingCount ?? 0) > 150;

  if (!tieneWeb) ligas.push({ servicio: SERVICIO_LANDING, prioridad: 'Alta' });
  if (altoVolumen) ligas.push({
    servicio: SERVICIO_B2B,
    prioridad: tieneWeb ? 'Media' : 'Alta',
  });
  return ligas;
}

Fragmento — búsqueda en Google Places

const response = await fetch('https://places.googleapis.com/v1/places:searchNearby', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-Goog-Api-Key': process.env.GOOGLE_PLACES_API_KEY,
    'X-Goog-FieldMask':
      'places.id,places.displayName,places.formattedAddress,places.rating,' +
      'places.userRatingCount,places.websiteUri,places.location',
  },
  body: JSON.stringify({
    locationRestriction: { circle: { center: { latitude, longitude }, radius } },
    includedTypes: tipos, maxResultCount: 20, languageCode: 'es',
  }),
});

Vercel

  1. Empuja el repo (este repo PS) a GitHub.
  2. Vercel → Add New Project → importar repo; detecta api/*.ts.
  3. Configura las 4 variables de entorno (URL, KEY, GOOGLE KEY, CORS_ORIGIN).
  4. Deploy. Endpoints: /api/prospectar y /api/health.
vercel.json
{
  "version": 2,
  "functions": { "api/*.ts": { "runtime": "nodejs20.x", "memory": 1024, "maxDuration": 30 } },
  "routes": [
    { "src": "/api/prospectar", "dest": "/api/prospectar.ts" },
    { "src": "/api/health",     "dest": "/api/health.ts" }
  ]
}

Render

  1. Render → New → Web Service → conectar repo GitHub.
  2. Build: npm install && npm run build
  3. Start: npm start
  4. Health check: /api/health; puerto render usa PORT por defecto.
  5. Crear servicio. Queda en https://TU-SERVICIO.onrender.com/api/prospectar.
